O padrão AAA

Bloco 1 · Tópico 1

Arrange, Act, Assert

Três fases

  • Arrange: preparar ambiente, instâncias, dados
  • Act: executar a ação sob teste
  • Assert: verificar o resultado esperado

Um teste com AAA claro se explica sozinho

AAA no domínio de Pedidos

describe('CarrinhoDeCompras', () => {
  it('aplica desconto de 10% acima de R$ 100', () => {
    // Arrange
    const carrinho = new CarrinhoDeCompras();
    carrinho.adicionarItem({ nome: 'Livro', preco: 120 });
    // Act
    const total = carrinho.calcularTotalComDesconto();
    // Assert
    expect(total).toBe(108.00);
  });
});

TDD

Bloco 1 · Tópico 2

Red, Green, Refactor

Não é técnica de teste

TDD é metodologia de design: o teste nasce antes do código.

O ciclo

Fase O que fazer
RED Escreva um teste que falha
GREEN Código mais simples possível para passar
REFACTOR Melhore mantendo os testes verdes

Benefício de design

  • Escrever o teste primeiro força pensar na interface antes da implementação
  • Gera naturalmente menor acoplamento e maior coesão

Siga o ciclo RED-GREEN-REFACTOR

  1. Escreva o teste (RED)
  2. Código mínimo (GREEN)
  3. Melhore (REFACTOR)

As 3 Leis de Uncle Bob

Bloco 1 · Tópico 3

As leis

  1. Não escreva código de produção sem um teste que falhe
  2. Não escreva mais teste do que o necessário para falhar
  3. Não escreva mais código de produção do que o necessário para passar

O erro mais comum

Escrever a classe inteira e só depois tentar fazer o teste passar.

TDD de verdade é passo a passo minúsculo.

Inversão de dependência

Bloco 2 · Tópico 4

e testabilidade

O problema: new escondido

class OrderService {
  aprovar(order: Order) {
    const gateway = new StripeGateway(); // concreto!
    return gateway.autorizar(order.total);
  }
}

Impossível trocar por um Stub no teste.

A solução: injetar

class OrderService {
  constructor(private gateway: PaymentGateway) {}
  aprovar(order: Order) {
    return this.gateway.autorizar(order.total);
  }
}

A classe depende de uma abstração, não do concreto.

Anti-patterns que matam testes

Bloco 2 · Tópico 5

Os 4 mais comuns

  • new interno de dependência concreta
  • Métodos estáticos que fazem I/O
  • Efeitos colaterais escondidos (calcula e também salva)
  • Estado global compartilhado entre testes

Efeito colateral escondido

// "Só calcula", mas também grava e manda e-mail
function calcularEAprovar(order: Order) {
  const total = order.calcularTotal();
  db.save(order);
  emailService.send(order.clienteEmail);
  return total;
}

Separe decisão (pura) de ação (efeito colateral).

Coverage

Bloco 2 · Tópico 6 · Extra

O que mede e o que não mede

Três métricas

Métrica O que mede
Line coverage % de linhas executadas
Branch coverage % de condicionais percorridos
Function coverage % de funções chamadas

100% não garante ausência de bugs

Cobertura mede o que rodou, não o que foi validado.

Busque qualidade de asserção, não métrica vaidosa.

100% de coverage, teste ruim
