Monitoramento e observabilidade

Bloco 1 · Tópico 1

Duas perguntas diferentes

  • Monitoramento: sinais que você já sabe que precisa observar. Um alerta por condição conhecida.
  • Observabilidade: responder o que você não previu, sem adicionar código no meio do incidente.

Logs estruturados

Bloco 1 · Tópico 2

Texto livre não se consulta

function registrar(evento: string, campos = {}) {
  process.stdout.write(
    JSON.stringify({ ts: Date.now(), evento, ...campos }) + '\n'
  );
}

registrar('pedido_recebido', { requestId, usuarioId: 42 });
registrar('gateway_timeout', { requestId, gateway: 'cartao' });

O mesmo em PHP

function registrar(string $evento, array $campos = []): void
{
    $linha = ['ts' => microtime(true), 'evento' => $evento] + $campos;
    fwrite(STDOUT, json_encode($linha, JSON_UNESCAPED_UNICODE) . "\n");
}

$requestId = bin2hex(random_bytes(16));
registrar('pedido_recebido', ['requestId' => $requestId]);

O request_id é o elo

Gerado na entrada, propagado em cabeçalho, presente em toda linha.

Sem ele, o log de cada serviço é uma ilha.

cat pedidos.log | jq 'select(.requestId == "a3f2...")'

Duas regras de conteúdo

  • Nunca segredo, token ou dado pessoal completo
  • Nível com critério: DEBUG, INFO, WARNING, ERROR

Se todo evento é ERROR, nenhum deles é

Métricas

Bloco 1 · Tópico 3

Três tipos

  • Contador: só cresce (requisições atendidas)
  • Medidor: sobe e desce (conexões ativas)
  • Histograma: distribui em faixas (latência)

O que medir

  • RED, para serviços: Rate, Errors, Duration
  • USE, para recursos: Utilization, Saturation, Errors

CPU baixa com 100% de erro é um sistema parado e “saudável”.

RED ou USE

Mini desafio 3 · 5 min

Requisições por segundo · CPU do container · % de 5xx · profundidade da fila · tempo de resposta · conexões no pool

Classifique em RED ou USE, e diga o tipo de métrica.

SLI, SLO e orçamento de erro

Bloco 2 · Tópico 5

O dilema do alerta

Alerta que dispara toda hora é ignorado. Alerta que nunca dispara não protege nada.

Os três conceitos

Conceito O que é Exemplo
SLI Medida da experiência do usuário % de checkouts com sucesso em < 800 ms
SLO Meta para o SLI, numa janela 99,5% em 30 dias
Orçamento de erro Fração que pode falhar 0,5% → 5.000 de 1.000.000

A consequência operacional

  • Orçamento consumido rápido → reduzir ritmo de mudanças
  • Orçamento sobrando → pode assumir mais risco

Combinado antes do incidente, entre produto e engenharia

Por que isso muda a conversa

Sem SLO: “acho que o sistema está instável” contra “acho que dá para lançar”.

Com SLO: 75% do orçamento consumido em um terço do mês. A regra já estava acordada.

Traces distribuídos

Bloco 2 · Tópico 6 · Extra

A árvore de spans

Um span é uma operação com início, duração e atributos.

O span de checkout tem filhos: estoque, gateway, banco.

Quando fica lento, o trace mostra qual filho concentrou o tempo.

OpenTelemetry

const tracer = trace.getTracer('pedidos');

await tracer.startActiveSpan('finalizar_pedido', async (span) => {
  span.setAttribute('pedido.id', pedidoId);
  await verificarEstoque(pedidoId);
  await cobrar(pedidoId);
  span.end();
});

Automático cobre infraestrutura. Manual cobre o domínio.

Instrumentar e definir um SLO

Desafio integrador · 45 min

Em dupla

O que entregar

  1. Logs JSON com request_id em todas as linhas do fluxo
  2. Contador por rota e status, e histograma de latência
  3. SLI e SLO do endpoint, com justificativa escrita
  4. Orçamento de erro para 1 milhão de requisições/mês

Verificação

Entrada Saída esperada
SLO 99,5% · 1.000.000 req 5.000 podem falhar
SLO 99,9% · 1.000.000 req 1.000 podem falhar
3.000 falhas com SLO 99,5% 60% consumido, restam 2.000

Sem dado pessoal no log. Sem id de usuário no rótulo do histograma.

Fechamento

  • Observabilidade: responder o que você não previu
  • Log: JSON, request_id, sem dado pessoal
  • Métrica: RED e USE, baixa cardinalidade
  • Percentil, nunca média
  • SLO: acordo com número, combinado antes

Dever de casa

  1. Log estruturado com request_id no endpoint principal
  2. Contador por rota e status, e histograma de latência
  3. SLI, SLO com justificativa, e orçamento de erro do mês
  4. Levar 3 dúvidas
