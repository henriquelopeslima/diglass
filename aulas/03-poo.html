Aula 3 — Programação Orientada a Objetos 💻

Full Cycle · Módulo 1 — Engenharia de Software e IA Aplicada

Objetivo de aprendizagem

Ao final desta aula, você deve ser capaz de:

  • Reconhecer que POO é um paradigma (não uma sintaxe)
  • Identificar e aplicar os 4 pilares em pelo menos duas linguagens diferentes
  • Entender quando preferir composição a herança

Introdução

  • POO é uma forma de pensar sobre código que transcende a linguagem
  • Um conceito como Encapsulamento é idêntico em TypeScript, PHP e Java — muda a sintaxe, não a intenção
  • Esta aula apresenta os 4 pilares com exemplos comparáveis em TypeScript, PHP e Java

Pilar 1 — Encapsulamento

  • Agrupar dados e comportamentos numa classe e controlar o acesso via modificadores de visibilidade
  • Benefícios:
    • Proteção de dados (validação antes de mudar)
    • Controle de estado
    • Flexibilidade de implementação
    • Manutenção de invariantes (ex.: saldo nunca negativo)
  • Modificadores de acesso (public, protected, private) — sintaxe idêntica nas 3 linguagens, mesmo significado

Pilar 2 — Herança

  • Reaproveitar atributos/métodos de outra classe e criar hierarquias conceituais

⚠️ Armadilha: cadeias longas (Veiculo → Terrestre → Automóvel → Carro → Ferrari) geram alto acoplamento e fragilizam testes.

✅ Solução: hierarquias rasas (máx. 2–3 níveis) e preferir composição (“tem um”) a herança (“é um”) para capacidades adicionais.

Pilar 3 — Polimorfismo

  • Um mesmo método se comporta de formas diferentes conforme a classe que o implementa
  • Elimina cadeias de if/else baseadas em tipo

Sem polimorfismo: cada tipo novo exige alterar todo o código cliente.

Com polimorfismo: cada tipo sabe se comportar via um contrato comum (interface/classe abstrata).

Pilar 4 — Abstração

  • Esconder complexidade e expor uma interface simples
    • bd.buscar("usuarios") em vez de gerenciar TCP/SQL diretamente

Diferença-chave: Encapsulamento protege dados; Abstração simplifica a interação.

Integrando os 4 pilares — Folha de Pagamento

  • Abstração: classe abstrata Funcionario define o contrato
  • Herança: especializações rasas (Gerente, Developer)
  • Encapsulamento: acesso seguro ao salário via getters
  • Polimorfismo: calcularBonus() se comporta diferente por tipo

Boas práticas relacionadas: Alta Coesão, Baixo Acoplamento, Responsabilidade Única (SRP).

Atividade prática sugerida

Modelar o sistema de folha de pagamento (ou domínio similar) implementando os 4 pilares na linguagem de preferência, comparando depois com a implementação de um colega em outra linguagem.

💻 Exemplo prático guiado

Modelando o Diário de Café em POO — polimorfismo nos métodos de extração:

abstract class MetodoExtracao {
  constructor(protected proporcaoAguaCafe: number) {}
  abstract preparar(doseGramas: number): string;
}

Polimorfismo — métodos de extração

class V60 extends MetodoExtracao {
  preparar(doseGramas: number): string {
    const agua = doseGramas * this.proporcaoAguaCafe;
    return `V60: despeje ${agua}ml de agua sobre ${doseGramas}g de cafe moido medio-fino, em espiral, por ~2:30min.`;
  }
}

class Aeropress extends MetodoExtracao {
  preparar(doseGramas: number): string {
    const agua = doseGramas * this.proporcaoAguaCafe;
    return `Aeropress: infusao de ${doseGramas}g de cafe com ${agua}ml de agua por 1min, depois prense por 30s.`;
  }
}

class PrensaFrancesa extends MetodoExtracao {
  preparar(doseGramas: number): string {
    const agua = doseGramas * this.proporcaoAguaCafe;
    return `Prensa Francesa: cafe grosso, ${agua}ml de agua, 4min de infusao antes de prensar.`;
  }
}

Por que isso importa

O código que chama metodo.preparar(dose) nunca precisa saber qual subclasse está usando — cada método de extração sabe se comportar sozinho.

Existe também um exemplo equivalente em Java/PHP na aula original, com a mesma ideia por trás de sintaxes diferentes.

Encapsulamento — a receita protege seu próprio estado

class Receita {
  private historico: string[] = [];

  constructor(
    private nome: string,
    private metodo: MetodoExtracao,
    private doseGramas: number
  ) {
    if (doseGramas <= 0) throw new Error("Dose deve ser maior que zero");
  }

  executar(): string {
    const instrucao = this.metodo.preparar(this.doseGramas);
    this.historico.push(`${new Date().toISOString()}: ${instrucao}`);
    return instrucao;
  }

  get totalExecucoes(): number {
    return this.historico.length; // ninguem de fora consegue alterar o historico diretamente
  }
}

Polimorfismo de novo — protocolos de pontuação

interface AvaliacaoSensorial {
  fragancia: number; sabor: number; acidez: number; corpo: number; docura: number; defeitos: number;
}

interface ProtocoloDePontuacao {
  calcularNota(a: AvaliacaoSensorial): number;
}

class ProtocoloSCA implements ProtocoloDePontuacao {
  calcularNota(a: AvaliacaoSensorial): number {
    return a.fragancia + a.sabor + a.acidez + a.corpo + a.docura - a.defeitos;
  }
}

class ProtocoloCupOfExcellence implements ProtocoloDePontuacao {
  calcularNota(a: AvaliacaoSensorial): number {
    return (a.fragancia + a.sabor * 2 + a.acidez + a.corpo + a.docura) / 1.2;
  }
}

Abstração — o resto do app não sabe que existe um banco

interface CafeRepository {

Juntando tudo

const receita = new Receita("V60 Etiopia Yirgacheffe", new V60(16), 20);
console.log(receita.executar());
// V60: despeje 320ml de agua sobre 20g de cafe moido medio-fino, em espiral, por ~2:30min.

const protocolo: ProtocoloDePontuacao = new ProtocoloSCA();
const nota = protocolo.calcularNota({ fragancia: 8, sabor: 8.5, acidez: 7.5, corpo: 8, docura: 8, defeitos: 0 });
// nota = 40 (escala SCA de 0-100 apos normalizacao)
