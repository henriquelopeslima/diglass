O valor econômico do QA

Bloco 1 · Tópico 1

Testar não é burocracia

Testar é reduzir o custo de mudar o sistema amanhã.

Não é “procurar bug por procurar”.

A regra dos dez (Boehm)

Fase Custo de corrigir
Requisitos / Design $1x
Dev / teste unitário $10x
QA / Homologação $100x
Produção $1000x+

O custo cresce ~10x por fase.

O princípio de Dijkstra

“Testes podem mostrar a presença de bugs, nunca a sua ausência.”

  • A suíte não prova correção
  • Ela reduz o risco a um nível aceitável
  • Funciona como rede de segurança contra regressão

A Pirâmide de Testes

Bloco 1 · Tópico 2

Mike Cohn

Três camadas

Camada Velocidade Isolamento
Unitário < 5ms Total (sem I/O)
Integração 100ms – 2s Parcial (DB/API)
E2E (UI) 5s – 30s+ Nenhum (sistema real)

Mais testes embaixo, menos no topo.

Analogia da casa

  • Unitário: testar a lâmpada na bancada
  • Integração: rosquear a lâmpada e checar a fiação
  • E2E: entrar na casa, ligar o disjuntor, checar a sala

Cada camada testa uma coisa diferente

Testes como documentação viva

Especificação executável

it('deve aplicar desconto de 10% para compras acima de R$ 100', () => {
  // ...

O nome do teste é o contrato do método.

Documentação que nunca mente

  • README pode ficar desatualizado
  • Teste quebra quando o comportamento muda
  • O CI garante isso a cada commit

Test Doubles

Bloco 2 · Tópico 5

Stub, Mock e Fake

Três papéis diferentes

Tipo O que faz
Stub Resposta fixa e combinada
Mock Responde e verifica se foi chamado certo
Fake Implementação simplificada mas funcional

Stub e Mock no domínio de Pedidos

// Stub: resposta fixa
const gatewayStub = {
  autorizar: () => ({ sucesso: true, transacaoId: 'TX1' })
};

// Mock/spy: registra chamadas
const emailMock = vi.spyOn(notifier, 'enviar');
expect(emailMock).toHaveBeenCalledWith(
  'cliente@email.com', 'Pedido aprovado'
);
