Aula 1 — Docker ⚙️

Full Cycle · Módulo 1 — Engenharia de Software e IA Aplicada

Objetivo de aprendizagem

Ao final desta aula, você deve ser capaz de:

  • Entender o problema que o Docker resolve (“funciona na minha máquina”)
  • Diferenciar imagem de container
  • Escrever um Dockerfile funcional
  • Executar containers com portas e volumes mapeados

O que é Docker?

  • Plataforma para empacotar aplicação + dependências em um container padronizado
  • Analogia do contêiner de transporte: a mesma unidade roda igual em qualquer lugar
  • Por que usar:
    • Consistência — “funciona em qualquer lugar”
    • Isolamento
    • Portabilidade
    • Eficiência — menos overhead que uma VM
    • Escalabilidade

Sem Docker vs. com Docker

Sem Docker Com Docker
Setup ~30 min de configuração manual docker run
Ambiente Risco de divergência entre máquinas Ambiente idêntico em ~1 minuto

“Funciona na minha máquina” deixa de ser desculpa.

Conceitos e arquitetura

  • Container: instância em execução de uma imagem (processo isolado com código, runtime e dependências)
  • Imagem: template read-only que define como criar um container
  • Dockerfile: receita textual com as instruções para construir a imagem
  • Registry / Docker Hub: repositório central de imagens

Fluxo básico

Dockerfile → docker build → Imagem → docker run → Container

Arquitetura cliente-servidor

Docker Client (CLI) → Docker Daemon (serviço em background) → Registry

Instalação e validação

docker --version
docker run hello-world
  • Instalação via Docker Desktop
  • docker run hello-world confirma que o daemon está acessível e consegue baixar imagens do registry

Rodando o primeiro container

docker run nginx
docker run -p 8080:80 nginx
  • -p 8080:80 mapeia a porta 80 do container para a 8080 do host
  • Container interativo:
docker run -it ubuntu bash

Comandos essenciais

docker ps                 # containers em execução
docker ps -a               # todos os containers, incluindo parados
docker images              # imagens disponíveis localmente
docker logs <id>           # logs de um container
docker exec -it <id> bash  # abre um shell dentro do container rodando
docker stop <id>           # para um container
docker rm <id>             # remove um container parado
docker rmi <imagem>        # remove uma imagem

Criando sua própria imagem

Estrutura de um Dockerfile:

FROM node:20-slim      # imagem base
WORKDIR /app            # diretório de trabalho dentro do container
COPY package*.json ./   # copia os manifestos primeiro (cache de build)
RUN npm install --production
COPY . .                 # copia o restante do código
EXPOSE 3000               # documenta a porta usada
CMD ["node", "dist/main.js"]  # comando executado ao iniciar o container

Build, execução e volumes

docker build -t meu-app:1.0 .
docker run -p 5000:5000 meu-app:1.0

Volumes: persistência e compartilhamento de dados entre host e container — essencial no fluxo de desenvolvimento:

docker run -v $(pwd):/app meu-app:1.0

Atividade prática sugerida

Em duplas:

  1. Escrever um Dockerfile para uma API simples (Node ou Python)
  2. Buildar a imagem
  3. Rodar o container com porta e volume mapeados
  4. Validar no navegador

💻 Exemplo prático guiado

Diário de Café — app de barismo hobbista que catalogará cafés, insumos, cuppings (avaliações sensoriais) e receitas de extração ao longo de todo o módulo.

Nesta aula, o objetivo é apenas dockerizá-lo.

diario-cafe-api/
  src/
  package.json
  Dockerfile
  docker-compose.yml
  .dockerignore

Dockerfile do Diário de Café

FROM node:20-slim
WORKDIR /app
COPY package*.json ./
RUN npm install --production
COPY . .
EXPOSE 3000
CMD ["node", "dist/main.js"]

docker-compose.yml

Sobe a API junto com o banco onde ficam os cafés, receitas e cuppings:

version: "3.9"
services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://barista:senha@db:5432/diario_cafe
    depends_on:
      - db
    volumes:
      - ./uploads:/app/uploads
  db:
    image: postgres:16
    environment:
      - POSTGRES_USER=barista
      - POSTGRES_PASSWORD=senha
      - POSTGRES_DB=diario_cafe
    volumes:
      - cafe_data:/var/lib/postgresql/data
volumes:
  cafe_data:

.dockerignore

node_modules
dist
.git
uploads/*.jpg

Por que essa configuração

  • O Compose cria uma rede interna automática: o serviço api enxerga o banco pelo hostname db (nunca localhost)
  • cafe_data é um volume nomeado: persiste o catálogo de cafés mesmo se o container do banco for recriado
  • ./uploads:/app/uploads é um bind mount: guarda no seu próprio PC as fotos dos grãos enviadas pelos usuários, útil pra debugar sem entrar no container

Comandos do dia a dia

docker compose up -d --build
docker compose logs -f api
docker compose down        # para os containers, mantém os volumes
docker compose down -v     # cuidado: apaga também o volume do banco
