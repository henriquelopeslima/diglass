Aula 5 — IA como Assistente

Full Cycle · Módulo 1 — Engenharia de Software e IA Aplicada

Objetivo de aprendizagem

Ao final desta aula, você deve ser capaz de:

  • Escrever prompts estruturados de alta precisão
  • Escolher a ferramenta de IA adequada a cada tarefa do ciclo de desenvolvimento
  • Usar IA para gerar testes/refatorar/documentar com segurança
  • Aplicar um checklist crítico de revisão de código gerado por IA

Introdução à IA Generativa

  • LLMs são preditores probabilísticos, não “oráculos”
  • Atuam como pares de programação
    • Analogia: um estagiário ultrarrápido que leu toda a documentação da internet, mas não conhece o negócio

Anatomia de um prompt de alta precisão

Papel + Contexto + Tarefa + Restrições

“Atue como engenheiro sênior… use TypeScript estrito, injeção de dependência por construtor…”

Técnicas de prompt

  • Few-Shot Prompting: fornecer exemplos de entrada/saída antes de pedir a solução
  • Chain-of-Thought: instruir a IA a “pensar passo a passo” antes de gerar código, forçando planejamento de arquitetura
  • Prevenção de alucinações: sempre validar métodos/bibliotecas sugeridos na documentação oficial antes do deploy

Ecossistema de ferramentas

  • GitHub Copilot: integrado à IDE, forte em autocomplete inline, docstrings e testes pontuais
  • Cursor / IDEs nativas de IA: indexam toda a codebase (embeddings), permitem refatoração multi-arquivo e busca semântica
  • Arquivos de contexto de projeto (.cursorrules / instructions.md): padronizam regras da equipe para não repeti-las em todo prompt

Debugging assistido e segurança

  • Debugging assistido: alimentar a IA com Stack Trace + trecho de código + versões de runtime/bibliotecas acelera o diagnóstico

🛡️ Segurança e privacidade: nunca enviar chaves de API, senhas, dados de clientes (PII) ou código proprietário crítico para modelos públicos sem garantia de política de retenção zero.

Uso prático — geração de testes

Pedir cobertura de edge cases que humanos costumam esquecer:

  • Valores negativos
  • Limites
  • Entradas nulas

Refatoração e documentação viva

  • Refatoração de código legado: peça primeiro que a IA explique o código antigo; só depois solicite a modernização (ex.: callbacks → async/await) mantendo os testes
  • Documentação viva:
    • Geração de specs OpenAPI/Swagger
    • Diagramas Mermaid.js
    • Mensagens de commit no padrão Conventional Commits a partir do git diff

Visão crítica — o perigo do copiar e colar

Aceitar sugestões sem entender cria sistemas frágeis que ninguém sabe depurar em produção.

A IA substitui a digitação de código, não a Engenharia de Software: responsabilidade técnica, arquitetura e decisão continuam humanas.

Checklist de validação de código gerado por IA

  1. O desenvolvedor consegue explicar o algoritmo linha a linha?
  2. Desempenho/complexidade adequados (O(N) vs. O(N²))?
  3. Conformidade com SOLID/Clean Code?
  4. Risco de licenciamento/direitos autorais?

6 níveis de autonomia

Framework complementar (Tom Taulli, a partir de Quinn Slack):

Nível Descrição
0 Sem IA
1 Completamento
2 Criação de código supervisionada
3 Automação supervisionada
4 Automação total
5 Autonomia liderada

Útil para discutir até onde a turma já opera e até onde deveria ir com segurança.

Temperatura do modelo

  • Baixa (0.1–0.3): código/depuração determinística
  • Alta (0.7–1.0): brainstorming arquitetural

Atividade prática sugerida

  1. Cada aluno escreve um prompt estruturado (Papel + Contexto + Tarefa + Restrições) para gerar uma função com testes
  2. Roda em uma ferramenta de IA
  3. Aplica o checklist de code review no resultado antes de aceitá-lo

💻 Exemplo prático guiado

Usando IA no Diário de Café — prompt estruturado para gerar testes do RegistrarCuppingUseCase:

[PAPEL]: Atue como Engenheiro de Software Senior especialista em TypeScript e testes automatizados.
[CONTEXTO]: Este e o RegistrarCuppingUseCase de um app de catalogacao de cafes e cuppings (protocolo SCA, nota de 0 a 100).
[TAREFA]: Gere testes unitarios com Vitest cobrindo: nota fora do intervalo 0-100, cafe inexistente no repositorio, e avaliacao duplicada para o mesmo cafe na mesma data.
[RESTRICOES]: Use mocks para CafeRepository (nunca banco real), siga o padrao AAA (Arrange-Act-Assert).

Resultado gerado pela IA

Sempre revisado antes de aceitar:

describe('RegistrarCuppingUseCase', () => {
  it('deve lancar erro se a nota final estiver fora do intervalo 0-100', () => {
    const repo = mockCafeRepository();
    const useCase = new RegistrarCuppingUseCase(repo);
    expect(() => useCase.executar({ cafeId: '1', notaFinal: 150 })).toThrow(NotaInvalidaException);
  });

  it('deve lancar erro se o cafe nao existir no repositorio', () => {
    const repo = mockCafeRepository({ existe: false });
    const useCase = new RegistrarCuppingUseCase(repo);
    expect(() => useCase.executar({ cafeId: 'inexistente', notaFinal: 85 })).toThrow(CafeNaoEncontradoException);
  });

  it('deve lancar erro se ja existir avaliacao do mesmo cafe na mesma data', () => {
    const repo = mockCafeRepository({ cuppingExistenteHoje: true });
    const useCase = new RegistrarCuppingUseCase(repo);
    expect(() => useCase.executar({ cafeId: '1', notaFinal: 85 })).toThrow(CuppingDuplicadoException);
  });
});

Refatorando código legado

// Antes: codigo legado com callback
function calcularProporcao(dose, callback) {
  buscarConfiguracaoMetodo((err, config) => {
    if (err) return callback(err);
    callback(null, dose * config.fator);
  });
}

Prompt: “Explique este código legado e depois refatore para async/await em TypeScript, mantendo o mesmo comportamento.”

// Depois: sugestao da IA, ja revisada
async function calcularProporcao(dose: number): Promise<number> {
  const config = await buscarConfiguracaoMetodo();
  return dose * config.fator;
}

Checklist de code review aplicado

Item do checklist Avaliação
Compreensão do algoritmo ✅ Sim — proporção simples, dose × fator, sem segredo
Desempenho/complexidade ✅ O(1), sem loops desnecessários
Conformidade com Clean Code/SOLID ✅ Nomes claros, sem callback hell, função faz uma coisa só
Licenciamento/direitos autorais ✅ Código trivial, sem risco de reprodução de trecho protegido

Se qualquer item desse checklist falhar, o código gerado pela IA é devolvido para ajuste — nunca aceito às cegas, mesmo parecendo correto à primeira vista.
