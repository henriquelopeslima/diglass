Formato

Parte 1 · Regras do jogo

Individual ou em grupo

  • Grupo de até 3 pessoas, ou individual
  • O escopo entregue é o mesmo nos dois casos
  • Em grupo, divida por módulo do sistema, não por tarefa de nota

A nota é individual

  • Commits e PRs no seu nome: o histórico é a evidência
  • Um CONTRIBUTORS.md dizendo quem fez o quê
  • Na apresentação, cada um defende a sua parte

Quem não aparece no histórico não tem o que ser avaliado.

Projeto A

Nível avançado

Projeto A — o sistema

  • Marketplace como monólito modular: catálogo, pedidos, pagamento
  • Módulos com fronteira explícita, não pastas soltas
  • Banco com volume: pelo menos 100 mil pedidos sintéticos

Projeto A — base e qualidade

Origem Entregável Ferramentas (exemplos)
M1 Compose que sobe com 1 comando, SOLID, 1 pattern justificado Docker Compose, ESLint
M1 Um Database Pattern aplicado e a decisão registrada Prisma, TypeORM ou Knex
M2 Testes unitários, de integração e de contrato de API Vitest ou Jest, Testcontainers, Pact
M2 Coverage acima do mínimo declarado no próprio pipeline Vitest coverage (v8), Codecov

Projeto A — entrega e operação

Origem Entregável Ferramentas (exemplos)
M3 CI com lint, testes, coverage e SCA de dependências GitHub Actions, npm audit, Trivy
M3 Dois ambientes, configuração no ambiente, segredos fora do código dotenv, GitHub Environments e Secrets, gitleaks
M3 Logs estruturados, métricas RED, 1 trace e 1 SLO declarado pino, Prometheus + Grafana, OpenTelemetry + Jaeger
M3 Uma feature flag e a estratégia de deploy escolhida Unleash ou GrowthBook, Render ou Railway

Projeto A — arquitetura e desempenho

Origem Entregável Ferramentas (exemplos)
M4 ADR com a alternativa descartada, C4 de contexto e de contêiner Template MADR, Mermaid C4, Structurizr
M4 OpenAPI 3.1 do catálogo e do pedido, com lint no pipeline Spectral, Redocly CLI, Swagger UI
M4 Plano de p95: cache com tolerância, idempotência da fila Redis, BullMQ ou RabbitMQ
M4 k6 em 3 estágios e relatório com gargalo, antes e depois k6, clinic.js, EXPLAIN ANALYZE

Projeto B

Nível simples

Projeto B — o sistema

  • Uma API de domínio único: pedidos, biblioteca, agenda, o que for seu
  • Um fluxo principal funcionando de ponta a ponta
  • Sem decomposição em módulos, sem exigência de volume

Simples não é incompleto: o fluxo tem que funcionar de verdade.

Projeto B — base e qualidade

Origem Entregável Ferramentas (exemplos)
M1 Compose que sobe com 1 comando, SOLID, 1 pattern justificado Docker Compose, ESLint
M2 Testes unitários do domínio e 1 teste de integração Vitest ou Jest, Supertest
M2 Coverage mínimo declarado e respeitado Vitest coverage (v8)
M3 CI verde: install, lint, test GitHub Actions, ESLint

Projeto B — operação e documentação

Origem Entregável Ferramentas (exemplos)
M3 .env.example no repositório, segredos fora dele dotenv, gitleaks
M3 Logs estruturados, 1 métrica e 1 SLO simples pino, prom-client
M4 README do primeiro dia e 1 ADR Markdown, template MADR
M4 OpenAPI do endpoint principal e 1 smoke test k6 com p95 medido Swagger Editor, Spectral, k6

Como escolher

  • B não é desistência: um B impecável vale mais que um A pela metade
  • A se já tem CI e testes rodando; B se começa esta semana
  • Declare o nível na primeira linha do README

Como a nota sai

Parte 5 · Avaliação

Rubrica

Critério Peso
M1 Funciona, código e design 35
M2 Testes e CI verde 20
M3 Ambientes, segredos e observabilidade 15
M4 Arquitetura, documentação e desempenho 30

Mesma rubrica para A e B: muda o tamanho da evidência, não o rigor.

Uso de IA

  • Permitido e esperado: foi metade do curso
  • Declare em docs/ia.md os prompts que importaram
  • A IA sugere alternativas; a decisão continua sendo sua
  • Código que você não sabe explicar não conta como seu

O que mais derruba nota

  1. Escopo inflado e nada funcionando
  2. CI vermelha, ou inexistente
  3. README que não deixa a aplicação subir
  4. Segredos commitados no repositório
  5. Teste sem asserção e número sem medição
